# External Cadence Protocol（外部节奏协议）

共享契约：长时运行任务（队列、watchdog、监控循环）对外界的轮询/心跳节奏
统一按本文件执行。`experiment-queue`、`monitor-experiment`、`watch` 引用本文。

## 轮询节奏

| 场景 | 默认间隔 | 说明 |
|---|---|---|
| 队列调度器轮询（queue_manager.py --poll） | 60s | GPU 空闲探测 + 状态检查，不必更快 |
| 监控循环读日志尾 | 30-60s | `tail -c` 有界读取，禁止整文件读入上下文 |
| watchdog 巡检 | 60s | 进程活性 + 输出文件新鲜度 |
| 远端 SSH 探活 | 120s | 失败 3 次才判定失联，单次失败只记录 |

## 心跳与失联

- 长时间任务必须写**可外部检查的心跳**：进程在 = 心跳在（screen 会话存活、
  日志 mtime 更新、pid 文件三者任一即可）。
- 判定失联前至少跨 3 个轮询周期；每周期把判定依据写入日志，禁止凭单次
  超时杀掉任务。

## Let a broken run fail visibly（让坏运行可见地失败）

- 不要静默重启、不要吞掉非零退出。失败必须落在结果账本
  （results.tsv / queue_state.json）里，带错误类别与时间戳。
- 自动重试只允许两类：OOM（队列内置 retry_wait 语义）与瞬时网络错误
  （重试 ≤3 次，指数退避）。其余失败直接终态，把人叫来。
- 重启任务必须换 attempt 命名空间（日志、产物均带 attempt 号），
  旧 attempt 的产物永不覆盖。

## 升级路径

节奏相关的异常（轮询滞后超过 2 个周期、心跳丢失、磁盘写失败）记入
`notes/`，并在 CHANGELOG 追加一行；连续两次同因异常必须停下汇报，
而不是继续放大循环。
