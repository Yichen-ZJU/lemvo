# 工作单元、结果交接与上下文

这是一份运行方式说明，不是新的科研审核表。工作单元不改变七步深度调研、关键论据全文核查、探索与确认的区别，也不改变现有 guided / unattended 模式。

## 从一项具体工作推进

控制器仍负责 owner、作业对账、等待、指导队列与运行结算；Orchestrator 决定下一项科研工作，执行端负责这项工作。`templates/work-unit.py` 由适配层调用 `prepare` / `settle`，将本轮任务与结果写入既有 `turns/<turn_id>/`，不会另建科学状态机。

任务目标应是可以动手的内容，例如“修改已有选择器并运行已授权 A/B 对照”，而不是“重新审核整个方向”。可以从当前用户指导、现有状态里的下一步、上轮交接继续。元数据不齐全时兼容已有项目，不等待任务表通过。

一个工作单元可以涉及一轮构思、同一实现的多步调试、一个实验批次、结果分析或写作。它不要求每次都调用新代理；工作规模由问题与运行状态决定，不人为拆成大量微轮。

## 项目连续，聊天可以轮换

- 连续修复同一实现时保留会话，复用工具上下文与缓存。
- 阶段/方法分支变化或上下文较大时，运行时可用当前任务包开启新会话；不把整个战役聊天作为唯一记忆。
- 新会话先获得当前目标、有效指导、相关结果与原件路径，再按需查看具体代码、论文或日志。
- 研究状态、实验结果、累计资源记录、用户授权、有效指令和活作业 `run_id` 始终沿用。新会话不是新研究，也不是重跑同一实验的授权。
- 在途训练继续；轮换发生在派发边界。已有 owner、恢复、作业去重与双模式语义保留。

`turns/<turn_id>/context-plan.json` 记录本轮为何 fresh 或 resume；`work-unit.json` 是本轮上下文快照，不取代 `research-state.yaml` / findings。完整历史留盘，读取窗口只控制默认工作集，不删除历史或科学事实。

## 结果首先是事实

适配层将本轮交接保存为 `work-result.json`；已有显式结果优先，缺省走兼容回传。结果不需要为了格式而创造实验或数字。

有意义的交接包括：做了什么改动、实际产物路径、哪些作业已完成/仍在跑、真实测量及其设置、工程异常、待解决问题和下一项方法动作。没有测量时标未知或未运行；实现失败不是方法家族被证伪；确认尚未成立不抹掉开发正信号。

例如下面是交接内容的说明，不是必须填满的模板：

> 已接好选择器接口并修复批处理；A/B 作业仍在跑，run_id 为现有登记值。当前没有新指标，不判方法失败。下轮读取该作业结果，再决定保留选择器还是修改路由条件。

进程退出码、运行结果、科学判断分开处理。`rc=0` 不能把未完成训练写成成功；`rc!=0` 不能自动把方向判为负。不存在或截断的结果继续按原有运行恢复处理，不伪造完整结果。

## 少读重复材料，保留深入能力

完整训练日志、文献与代码保留在磁盘；默认交接当前配置差异、相关测量、必要错误摘要和原件路径。稳定角色说明与已读规则不需要每轮全文重读；新任务需要或证据不足时，仍读取相应章节和完整原件。

文件指纹只提示内容是否变化，不是科研有效性的判据。未知指标不能补零；程序不能猜单位或从一次失败推出整个方向无效。摘要保留条件性负结果、已有正信号、未决问题和来源位置。

普通作业等待用程序，不需模型反复报告“还没结束”。新指导、作业结束或可行动异常才唤醒下一项工作。调研请求依旧走现有调研管线，实验工作单元不反复重开综述或全局审判。

## 兼容与边界

旧项目没有工作单元或显式结果时仍可推进；缺少这些文件不是准入门。用户直接从可跑代码开始时照常进入实验，不强制回到构思。guided 在既有安全交接点等人，unattended 在真实授权内继续，不因新增格式多问一次。

这一机制管理输入体积和交接，不承诺固定节省比例。实际收益需按同模型、同任务记录输入/缓存/输出、模型调用、有效代码与实验；高缓存率不等于低总输入。

## 可选结果命令与上下文策略

正常运行无需手动调用 `prepare` / `settle`。执行端需要显式交接时，可在项目目录使用当前安装目录中的 helper，`turns/<turn_id>` 取自本轮任务包，例如：

```bash
python3 /path/to/research-orchestrator/templates/work-unit.py report turns/<turn_id> \
  --status partial --summary "选择器实现完成，已登记的A/B训练尚在运行" \
  --next "读取现有A/B作业结果并修订选择器" --artifact src/selector.py
```

可用状态为 `completed` / `partial` / `waiting` / `failed` / `unknown`，表示本项工作状态，不是论文成熟度或方法价值评级。可选 `--metrics-file` 引用真实JSON测量；`--evidence-scope` 保留测量范围；不需要为了运行捏造测量。未写显式结果也会兼容交接。

项目可选 `.lemvo-context-policy.json`：

```json
{
  "mode": "auto",
  "max_session_turns": 12,
  "max_context_tokens": 120000,
  "file_excerpt_chars": 5000
}
```

`auto` 在当前实现内续接，阶段/分支变化或上下文达到策略值时可轮换；`resume` 偏向持续续接，`fresh` 每项派发用当前状态包。实际选择写入本轮 `context-plan.json`。`max_session_turns` 是会话轮换策略，不是实验轮数上限，也不是停止研究或扩预算的门。token阈值只依据可观测的单请求上下文，不能用累计token假装当前窗口。

`file_excerpt_chars` 限制默认原件摘录，不删除原件；超出部分会指向完整路径。用户新指令与授权必须保留，不用裁剪窗口悄悄删去限制或新增许可。需要深入证据时继续读取原件，而不是把摘录当全文。
