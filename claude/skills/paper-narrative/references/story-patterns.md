# Six Scientific Story Patterns（六种科学叙事范式）

由 `paper-narrative` 选择并维护主线。六种范式**不是排名，也不是六项必过
门槛**：通常选一个最适合的主线，必要时融合其他路线；都不适配时，允许
采用任何其他清晰的证据叙事。每种范式给出：适用情况、论证推进、全文
组织（Intro / Method / Experiments / Conclusion 各做什么）、表达校准
（防止越界的护栏）。

选择依据是贡献的真实形态（已成立的部分），不是哪种故事"听起来更大"。
研究尚未完成时，把待检验的想法与已成立的发现分开写进叙事计划；结果
变化后允许换主线。

范式回答**论证立场**；行文骨架（Intro 与全文的段落组织模板）见
`references/conventional-structures.md`——两者正交：选定范式后通常
仍按常规骨架行文，内容按范式主线填充。

---

## 1. 根因手术刀（Root-Cause Scalpel）：从现象走向解释，再给针对性方案

**适用情况**：研究不只发现性能差异，还对瓶颈或失效机制提供了有价值的诊断。

**论证推进**：具体失效现象 → 排查竞争解释 → 定位关键因素 → 针对该因素设计方案 → 验证解释与方案。

**全文组织**：
- Intro：用具体矛盾提出问题，不只泛称"现有方法存在不足"。
- Method：解释设计为什么针对诊断结果，而不是罗列模块。
- Experiments：区分诊断证据、针对性验证和最终效果。
- Conclusion：凝练获得的机制认识或设计启示。

**表达校准**：只有相关性分析时，把它作为观察或解释线索，不升级为"已证明的因果根源"——但这不影响明确表达已经成立的性能或诊断贡献。

## 2. 反直觉重构（Counter-Intuitive Reframing）：重新审视一个默认设定

**适用情况**：某个常用设定、设计习惯或公认优势，在明确条件下存在被忽略的代价，并提出替代视角。

**论证推进**：默认设定 → 可观察的矛盾 → 解释矛盾 → 重构问题或设计 → 比较替代方案。

**全文组织**：
- Intro：清楚交代被重新审视的具体设定。
- Method：从新的理解推出设计选择。
- Experiments：直接检验原设定与替代方案，体现实验的比较条件。
- Conclusion：留下修正后的认识或更有效的设计原则。

**表达校准**：不要把局部发现写成推翻整个领域；不要为制造反转而把已有研究写成明显愚蠢的稻草人。

## 3. 理论照亮经验（Theory Illuminates Practice）：用形式化结果建立解释

**适用情况**：贡献主要来自定理、界、复杂度、表达能力、等价关系，或理论支持的设计。

**论证推进**：尚未解释的问题 → 清晰定义与假设 → 核心结果 → 证明思路 → 推论或设计意义。

**全文组织**：
- Intro：说明理论结果解决了哪个具体认识缺口。
- 正文：先让读者理解结果的含义，再进入必要的技术细节。
- 图、构造例子和实验按需辅助理解；证明承担其应承担的论证责任。
- Conclusion：说明现在能够确定什么，以及这一结果带来的认识。

**表达校准**：理论论文不必为符合通用模板而增加训练实验、SOTA 表格或模块消融；定理的适用条件属于结果本身，应清楚呈现，而不是放在最后当作自我否定。

**渐近不外推（检查项）**：Θ/O/Ω 只给出常数因子内的量级——禁止从
Θ(√d) 之类的渐近结论推出"维度翻倍、半径乘 √2"这类精确比例或常数；
材料没给的证明步骤、反例构造细节不得补写；前人文献状况没有来源时
不得断言"此前没有量化关系"，直接用问题本身组织开篇。

## 4. 新基准暴露失效（Benchmark Exposes Failure）：让模糊问题变得可测量

**适用情况**：核心贡献是新的任务定义、数据集、评测指标或实验协议，并揭示原有评测遗漏的问题。

**论证推进**：原评测遗漏什么 → 定义需要测量的能力 → 构造并验证测量工具 → 展示有解释力的结果 → 更新对能力的判断。

**全文组织**：
- Intro：解释为什么原有指标不足以回答目标问题。
- 构造部分：说明任务、指标与研究问题的对应关系。
- 实验：既展示模型表现，也说明基准的区分能力与测量有效性。
- Conclusion：总结新评测让我们看到了什么，以及它改变了怎样的判断。

**表达校准**：不要求基准论文必须额外提出一个新模型或解决方案——揭示并可靠测量一个重要问题，本身可以是完整贡献。

**与 benchmark 行文骨架的区分**：本范式是论证立场（把"让模糊问题可
测量"当研究贡献的主线）；benchmark 论文的常规六段行文骨架见
`conventional-structures.md` 骨架 2——立场与骨架可叠加。选了本范式
不等于要"另造新范式"：论文本体是 benchmark 时，行文走 benchmark
骨架。

## 5. 社会价值叙事（Societal Value）：把技术放回真实需求与约束

**适用情况**：研究的重要性来自明确的使用者、应用需求、现实约束或错误代价。

**论证推进**：具体需求 → 现有方案与现实约束的冲突 → 技术选择 → 与需求对应的验证 → 已建立的实际价值或应用意义。

**全文组织**：
- Intro：明确谁遇到了什么困难，不只写宏大的社会愿景。
- Method：解释设计如何回应资源、数据、可靠性、公平性或使用条件。
- 实验：指标与实际需求相对应。
- Conclusion：回到研究已经改善或推进了什么。

**表达校准**：区分已测量的影响与有依据的应用潜力。只有模拟评测时，不宣称已产生现实部署收益；同时也不要因此把已验证的技术贡献写得畏缩。

## 6. 极简统一美学（Unifying Principle）：用共同原则组织多个问题

**适用情况**：研究通过同一种表征、接口、目标或机制，解释或处理此前分散的问题。

**论证推进**：分散方案的共同结构 → 统一原则 → 不同任务如何由它导出 → 覆盖范围与收益 → 更清晰的整体认识。

**全文组织**：
- Intro：提出值得统一的共同问题。
- Method：讲清统一机制与各任务之间的映射，而不是用一个包装层藏住多个独立模块。
- Experiments：展示统一机制确实覆盖了哪些任务，以及相应的性能、成本或简化收益。
- Conclusion：提炼共同的组织原则。

**表达校准**："统一"需要体现实质上的共同机制；不要为美学叙事删掉必要设计；也不要求每项工作都追求一个接口解决所有问题。

## 主线与结尾落点的对应

不同主线在 Conclusion 留下不同的认识，结尾落点随之变化：

| 主线 | 结尾留下的认识 |
|---|---|
| 根因手术刀 | 我们理解了什么关键因素及其设计意义 |
| 反直觉重构 | 应如何修正原来的设定 |
| 理论照亮经验 | 已经严格建立了什么关系 |
| 新基准暴露失效 | 现在能测量和区分什么 |
| 社会价值叙事 | 研究推进了什么具体需求 |
| 极简统一美学 | 多个问题背后存在什么共同原则 |

结尾的默认任务是：回答核心问题 → 凝练已成立的贡献 → 说明它带来的认识
或意义。结尾不应只是摘要改写、指标复述或模块清单。真实边界、会议要求
和有价值的未来方向仍应妥善呈现，但不强制它们成为最后的落点。
