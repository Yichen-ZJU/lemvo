# 事件等待与退出续接

这份说明约定运行时怎样等待和唤醒，不增加科研评审、方向裁决或资源许可门。
实现、训练、结果、有效指导和累计账本仍沿用现有项目。

## 两种 owner，不重复运行研究主脑

- 由 Lemvo 启动的课题：`lemvo-run.sh` 是唯一的程序 owner。它派发 CLI 工作、
  对账后台作业，在新结果或可行动事件到来时继续。不要另起原生 owner 抢同一项目。
- 直接启动原生科研 CLI 的课题：独立原生 owner 负责该 CLI 的进程生命周期，
  并复用原有 session、研究目录和结果。CLI 正常返回只表示本轮结束；没有正在运行
  的 CLI 来接收原生 Monitor 回调时，不能把这次返回视为整个研究已完成。

控制器/原生 owner 之间必须检查已有身份和所有权。接管先采用已有结果和作业，
不重启已在训练的 producer、不重开历史暂停团队，也不重新初始化研究。

## 等待只观察外部事实

模型负责方法构建、结果解释和下一步决策。进程存活、退出码、终态文件和队列
状态由普通程序等待；CPU 下载、文件搬运和判分不因为名字叫实验就占 GPU 等待。

当当前分支只剩外部等待时，登记真实 producer 的进程身份、原件路径及唤醒条件，
保留当前工作，然后让出模型回合。不要重复执行“sleep → tail/ps → 模型 → sleep”
作为保活。CPU 程序可以轮询状态，不需要轮询时再调用模型。

每条分支分别判断完成/失败/身份丢失。某个结果先到，就形成它自己的终态事件，
不应一直等到同项目最后一个长任务结束才交接。事件按生产者身份、run_id 和终态
版本去重；成功交给当前科研会话后才确认消费。半写 JSON、缺测量或实现报错不
变成科学负结论，也不据此否定整个方法家族。

owner 在没有科研 CLI 时仍须存在：普通等待不启动模型；新结果、新指导或真实
异常到来，才派发一次相关工作。用户停止/暂停与研究完成保留现有优先级。
有活跃主会话时不另开第二个主脑；当前轮可安全收尾后再交接指导。

## Claude 项目级 hook 接线

在实际 CLI 启动前，运行时调用安装器：

```bash
python3 /path/to/templates/configure-event-runtime.py install \
  --root /path/to/project --engine claude --templates /path/to/templates
```

正常新课题由程序调用，用户不需要再手工配置一遍。安装器只合并项目里的
`.claude/settings.local.json`：PreToolUse（Bash/TaskOutput）、Stop 和 SubagentStop。
已有权限、插件和其他 hook 保留，不添加危险权限。原现场维护 hook 不被无差别删除。

事件 helper 复制到项目 `.runtime-events/runtime/<source-hash>/`，hook 指向这个固定
版本，避免刷新源文件时正在执行的解释器读到半个文件。更新生成新目录，旧版本不
覆盖。配置或原始 JSON 损坏时不覆盖原件；程序报告 `active=false` 和原因，不把
“安装未启用”当成科研方向失败。

`.runtime-events/installation.json` 保存实际引擎、源路径/哈希、版本脚本和配置路径。
**配置已写入不等于现有 CLI 已加载。** 接线适用于下一次实际加载项目设置的调用，
应以真实 hook 记录、producer 等待和唯一唤醒确认效果，不能仅凭文件存在宣布成功。
已有 `disableAllHooks` 或本安装器显式禁用偏好保留，不自动强开全局设置。

## Codex 边界

Codex 不读取 Claude 的这套原生 hook。`--engine codex` 明确返回
`codex_controller_only`，不假称已经保护 Codex 原生内部工具轮询。
Codex 继续使用现有 jobs、结果回执、控制器和进程 owner 契约；不能把 Claude
hook 安装测试当作 Codex 内部等待测试。

## 怎么判断实际生效

观察的是运行行为，不是新增科研验收门：等待真实 producer 的期间没有新增模型
请求；producer 终态后恢复一次；同一终态重复读取不重复派发；主 CLI 退出但研究
未结束时 owner 仍能继续。区分“有效地等待”与“主会话死掉所以零 token”。

等待类型识别和 hook 都有能力范围，不能承诺拦住所有任意脚本内部轮询。
必要的调研、实现和实验不因本机制增加审核，也不因省 token 缩减验证数据。
