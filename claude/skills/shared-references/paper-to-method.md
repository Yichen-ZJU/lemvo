# 从论文到可实施方法（Paper to Method）

用于“基于这篇论文发散 idea”、从具体瓶颈构造方法，或把已有候选改出下一版。
这是现有构思技能的按需设计工具，不是新技能、审核阶段或实验准入表。
它不替换独立调研任务的原有流程；读论文作为本次设计输入时，不额外重开综述。

## 以论文为起点

先读种子论文的方法、必要实验和所引用的关键机制；有官方代码且实现细节影响
设计时，定位相关模块。把它还原为一条可改的路径：
**输入/可用信息 → 监督或反馈 → 表示 → 核心操作 → 训练/决策 → 最终输出**。
保留作者做了什么、其结果在哪些条件成立；把自己的解释和未证实局限标为假说。
只需在现有笔记记录对设计有用的部分，不要求新建完整“论文解剖”文档。

从路径里找可变处，而不只沿 limitations 列表做补丁：固定了什么、信息在哪丢失、
哪些操作耦合、什么有效机制还能扩展。问题写成“什么在何种条件下受限”，不要
把“缺少我想加的模块”当作原因。没有证实局限时，可以提出待测限制或探索新
能力，不必先诊断证明失败才允许设计；也不凭空断言原方法存在缺陷。

用已有阅读识别直接近邻、经典做法和作者已做的消融；缺一处关键事实再定向读。
不把换术语当新方法，也不为证明“绝对原创”无穷搜索。近邻重合可以直接作为
实现起点；精确重合限定原创声明，不封死增量、组合、迁移或条件改变后的开发。
文献稀少、代码未公开或机制未证明不自动阻止提出可适配的设计。

## 先选设计动作，再展开机制

按当前机会选择有用动作；操作库是词汇，不是必经模板或逐项核验清单。
已有明确改法直接实施/交接。需要发散时，给少量实质不同的方案，数量由用户
目标和有用设计决定，不强制同时包含“保守版/激进版”，也不强制多个模块。

| 可变结构 / 适用机会 | 可实施的设计动作 | 怎样落到代码与直接比较 |
|---|---|---|
| 某算子、表示或位置限制能力/成本 | 替换、移动或重参数化它；保留其他路径 | 指明输入张量、输出张量及被替换调用；与原操作在同一开发任务比较 |
| 监督缺失、稀疏或与目标错位 | 从已达成结果重标注、轨迹配对、可得反馈或结构关系构造监督；也可引入已授权的新信号 | 说明标签/反馈怎样产生、进入哪个 loss/采样步骤；对比原监督，避免把同信息换名当新增信息 |
| 目标或粒度遮蔽关键行为 | 改 token/step/trajectory/episode 级目标、信用分配或训练顺序 | 指明梯度作用位置和估计目标；先比较对应行为及最终任务量，不要求额外理论证明 |
| 迭代/生成过程继承了固定选择 | 把固定起点、步序、工具时机、搜索宽度或中间状态变成条件化选择 | 给出选择输入和改变哪个动作；对比原固定策略，计入实际新增调用成本 |
| 不同样本、模态、阶段被同一规则处理 | 按能观察到的差异分解，再分别处理或路由 | 指明分组信号及各支路读取什么；同数据下对比统一规则，不能借封存 test 标签路由 |
| 多条任务路径重复学习相似结构 | 共享表示、接口或目标；保留必要差异 | 指明共享对象及各任务如何消费；比较质量、干扰或成本，不以“统一”本身当收益 |
| 已知几何、关系、对称性或守恒结构有用 | 将结构编码进表示/算子，而非只加软惩罚 | 给出具体约束参数化；比较任务效果与相关结构行为，未知性质不冒充保证 |
| 原表述难以求解或搜索 | 改写成有成熟求解器的对象、连续松弛或摊销预测 | 说明变量/目标如何对应及如何恢复原任务输出；和直接版本比较，不只改数学记号 |
| 两种机制各解决一处实际困难 | 重组数据流，或拆出独立求解子问题 | A 产生什么，B 在哪消费，怎样影响最终动作/梯度；一个操作够用就不加组件 |
| 有效性依赖某个可修订假设 | 改信息条件、交互方式或问题设置，建设覆盖新条件的版本 | 保留原版本证据，明确新版本可见信息/目标；按新条件比较，不把新设定冒充原条件胜利 |

从所选动作继续写实际运算、信息流与接口，而不是只给模式名字。例如“引入
反馈”还需说明反馈从哪里来、谁何时读取、改变哪个学习或推理操作。量级未知
就未知；新监督的可靠性或收益是实验问题，不为提案编造效果数字。

## 用最直接版本帮助设计，不用它设门

想一个可运行的朴素版本：哪些部分先不改，最小新操作是什么？若不够，当前
设计具体补哪一处？答案可以是待测假说。朴素版有效就保留、继续改进或诚实
呈现其增量，不为了“像研究”强行复杂化，不要求先证明简单方案失败。
组合方案说清中间对象的生产者与消费者；诊断报告或一张评分表本身不算改变
模型的方法。新设计可以仍是原创假说，不必先找到对应模式或凑齐证据。

## 交付有实现落点的候选

沿用 grounded-ideation 的现有候选记录或短笔记，不另造 schema、状态机、评分
和审批。对每个有价值的候选说明：

- **继承什么**：种子论文的操作、必要条件和已知结果，给节/式/代码引用。
- **具体改什么**：输入、输出、运算/损失/状态更新；必要时几行伪代码。
  已读到的文件才称代码落点，未实现模块明确写“拟新增接口/待适配”。
- **为什么可能有用**：哪个操作有望改变哪个任务行为；区分事实与预测。
- **第一项比较**：保留的原方法/朴素版本、候选、开发数据和目标指标；结果
  将怎样决定保留、改下一版或暂存。选择相称规模，不用小试替代必要的大规模验证。
- **差异与不确定处**：最近邻已做了什么、本方案改了什么；未查清标暂定，
  不用形式完整性或创新评分决定是否可以开发。

提案请求交付具体设计即可，不擅自启动训练。已有实验授权且实现就绪时，把
source_refs / concrete_change / transfer_map / next_min_probe 与父实现直接交给
现有 Forge/Autoresearch/Pro 后端；不再请求一次构思评审。guided/unattended
沿用项目唯一模式，原有权限与资源规则不变。

收到结果后按“保留什么 → 观察到什么 → 改哪里”产生子版本。同一个作用对象
允许换实现、条件、目标或信号；一次负比较不生成整族禁令，也不撤销旧正信号。
没有可信下一步可以暂存，不强制无限修订或按固定失败次数判方向死亡。
