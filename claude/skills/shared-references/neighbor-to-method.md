# 用近邻机制构造方法（Neighbor to Method）

用于论文发散、具体瓶颈和已有方法修订。近邻是可复用的程序与研究经验，先参与
生成，而不是生成完才用于裁决。本文是现有构思中的设计帮助，不是新阶段、
资格表或“必须比所有近邻强”的开工门。

## 把可用方法带进生成上下文

先使用现有论文笔记、Reusable Assets、代码和研究结果；针对会改变设计选择的
空缺，再读相应原文/实现。按问题、实际操作、经典做法及其他领域的同义操作找
近邻，不只搜新候选的自造名称。来源够用就进入设计，不按固定论文数补齐检索。
独立调研仍沿用原有流程；本次方法设计不自动重开整套调研和审核。

把最有用的源机制压缩到能复用的程度：它读什么信息/状态，计算哪个量，哪个
操作消费这个量，怎样改变梯度、动作或求解过程；必要条件、实际证据和代码/节/式
引用随行。论文标题、抽象贡献和“它研究过X”不能代替实际操作。可写在既有
source_refs / transfer_map 或笔记里，不新增固定字段或逐篇填表。

生成者实际读取选中的笔记内容。交接用现有 construction_context.py 时，可用
`--methods <已有机制笔记>` 把内容放进同一上下文，可重复指定少量相关文件。
脚本只读转发，不检索、不评分、不挑候选；缺少可选笔记就沿用可用资料，明确
未知。不要为调用脚本而新建本来不需要的记录，也不要只传一个无人打开的路径。

## 用“源操作 → 当前条件 → 适配操作”展开候选

选择一个可信实现起点，而非假设种子论文就是最强或最近的基线。它可以来自
种子论文，也可以来自更贴近本次目标的近邻、经典求解器或其可用组合。
接着把目标条件具体化：输入/监督能看到什么、决策发生在哪个状态、反馈何时
到达、表示保留什么、多个操作如何耦合。条件差异是设计材料，不要求先证明
原方法失败。值得探索的新能力也可成为目标，不必总从作者的 limitations 出发。

从这些条件推导需要的实际适配，按适用性选动作：

| 源机制在目标条件下遇到什么 | 怎样建设适配 | 在实现里写到哪里 |
|---|---|---|
| 反馈量能算出，却在错误的时间/位置消费 | 改反馈的消费位置、信用分配或更新对象 | 谁计算、谁读取、改变哪个 loss/动作/状态更新 |
| 原方法把相关过程独立处理，或将异质情况混成一个量 | 显式处理耦合，或按可观察状态分解 | 条件变量怎样进入目标/路由/求解；保留哪个共享部分 |
| 原算法依赖本任务没有的信息 | 用可得信号估计、重标注、蒸馏或重新求解；也可提出授权内的新信息路径 | 信号的生产步骤、使用时机、误差怎样影响任务输出 |
| 新量只被记录，未改变模型行为 | 把量接到学习、搜索或动作选择中，或移除无用组件 | 接口的生产者和消费者；真实调用和梯度/控制流 |
| 多个模块能复用，但接口/估计目标不一致 | 转换对象或目标，使两个机制能在同一任务协同 | 中间张量/样本/状态的类型、来源和消费关系 |
| 直接复用已经能解决当前问题 | 采用它作为父实现，再选择值得发展的新条件、能力或成本目标 | 先保留可用版本；无需为了“创新”重造同一算法 |

这是构造候选，不是要求逐行查完上述表。直接移植、参数改进和较大机制变化
都可选；既有方法覆盖了第一直觉时，复用它作为新起点，向尚有价值的条件或
能力展开，而不是重复包装、删除方向或强行加深复杂度。

## 在设计时辨清新操作做了什么

给出新公式或组件时，顺手展开它实际改变的量：可见信息、梯度方向、样本权重、
决策时机、搜索/求解空间，还是仅改写了同一运算。停止梯度、归一化、mask 和
聚合可能让“新对比目标”实际只是重加权；按真实作用命名，并决定怎样利用或
继续发展它。局部展开足以说明时就用，不开额外数学审查或诊断流程。

“加一个loss/权重/模块”只说明容器，还没说明方法；继续说它消费哪个源机制，
处理目标条件的哪处问题、怎样影响最终任务。也不因改动简单就否定它：一个
简单操作若利用了真实结构并有实际作用，可以是好的研究起点。

选择首项开发比较时，把最能解释新增作用的直接版本带上。例如新增监督可能
需要对比普通同量监督，额外观察可能需要对比相近信息/成本的直接版本。对照
在本轮实验里回答“新操作是否有额外作用”，不成为实验前的资格审查，不要求
所有近邻/全部场景都跑完，也不强制一套固定消融矩阵。

## 输出与实施沿用原接口

在已有候选里串起一条可执行说明：**借了谁的哪个操作 → 当前条件使哪里值得
改变 → 改哪个运算/信息或决策路径 → 第一项实现和比较**。source_refs 保留
原文/代码引用，transfer_map 说明保留与适配，concrete_change 指向文件/拟新增
接口，next_min_probe 使用直接父方法或相关近邻。无需新增必填字段。

区分原文结果、新设计预测和待查事实。原机制的准确率不移作组合方法的结果；
领域不同不自动等于机制不同，形式相似也不自动等价。原文未提供的条件保留
未知，不为证明差异无限搜索。原创假说可没有源机制，使用当前可得材料即可。

把实际机制内容连同候选传给 Forge/Autoresearch/Pro 执行端；实施时复用已有
父实现，不因标题不同重新造一遍。实验后保留有效部分，用观测修订操作和
条件；小正信号可以继续建设，局部失败只更新对应版本。没有可信改法可以
暂存，不能由一次相似或负结果推出整族禁令。
